Plan : [PLAN-REFRACTION-HORIZONS.md](../../PLAN-REFRACTION-HORIZONS.md), phase Q1. Commencée le 2 novembre 2026, sur kerr-mini
(M1, plein écran, page 1600 × 1000), F-35 en cockpit, vue figée. Outils : `tests/e2e/zz-visprobe.e2e.test.ts` (les passes, en

## Ce que la mesure a montré (avant de toucher au code)

Paris bas (450 m), décor chargé (32 000 bâtiments), image GPU ~45–49 ms :

| Coupé | Image GPU | Matériau | Visibilité | Ombrage du décor |
|---|---:|---:|---:|---:|
| rien | 48,9 | 14,3 | 5,4 | 6,5 |
| les anneaux du relief | 43,4 | — | 5,1 | 9,0 |
| les arbres | 43,9 | 12,7 | 4,8 | 6,1 |
| **les bâtiments** | **34,9** | 15,7 | **1,5** | **0,4** |
| les boîtes | 47,8 | 16,6 | 3,5 | 7,5 |
| les maillages | 47,2 | 14,4 | 4,8 | 7,0 |
| **les marques des ponts** | **40,0** | 13,6 | 3,8 | **0,4** |

- P1 (les anneaux du relief en blocs) ne paierait presque rien : ~0,4 ms. Écarté pour l'instant.
- Les bâtiments coûtaient ~9–10 ms : leurs boîtes non triées (visibilité) et les marques des ponts, dont les pixels partaient au
  noyau des rayons (ombrage).

## Fait

1. **P2 — les boîtes triées sur le GPU** (`c7056a8e`) : `cullBoxes` range les boîtes dans le champ en deux listes (bâtiments,
   parties de ponts) ; la visibilité 5,2–5,6 → 3,1 ms ; image identique à 0,09 % de pixels près.
2. **Les ponts en vrais maillages** (`bf1249c3`, demandé par Sam) : leurs tabliers, parapets et piles ont leurs triangles, dessinés
   comme ceux des bâtiments (marque 3,25, pierre, sans fenêtres, avec leur ombre) ; plus de marques. À la Seine (pont Alexandre III,
   150 m) : l'ombrage des ponts 11,7–15,1 → 0,4 ms, l'image GPU 53–58 → 44–45 ms.

## Le matériau du sol (`earth lite`) — le premier poste

| Partie coupée (`liteSkip`) | Paris | Chamonix, Soleil bas |
|---|---:|---:|
| rien | 13,4–14,4 | 18,5–21,0 |
| la passe seule (1024) | 0,8 | 0,8 |
| toutes les parties (1+2+4+8+16+32+64+128+4096) | 6,4 | 8,6 |
| l'eau / les ombres du décor / l'ombre du relief | −2,2 / −1,5 / −1,4 | ~0 / — / — |
| les surfaces / la normale fine / les ombres des nuages | −1,6 / −2,0 / −1,1 | ~0 |
| les arbres / l'imagerie / la lumière simple | −1,8 / −3,3 / −3,2 | ~−1 |

Aucune partie ne domine : le cœur de la lumière (ciel, air, Soleil) ~6–9 ms, chaque partie 1–3 ms. Le noyau fait 6 100 lignes une
fois ses fonctions recopiées, dont 44 % pour l'ombrage des arbres (`sceneryTreeLite`) — sur Apple, ses registres pèsent sur tous
les pixels. Testé (A/B `litetrees`, kerr-mini) : une version **compilée** sans les arbres ne gagne rien de plus que leur coupure à
l'exécution (Paris 12,2–13,3 contre 12,5 ms ; Chamonix 17,2–18,0 contre 18,4) — la taille du noyau n'est pas la cause, les arbres
restent dans le matériau. Le matériau ne baissera qu'en ombrant moins de pixels ou chacun moins cher : Q6 (la reconstruction
temporelle, le taux d'ombrage) plus que Q1.
